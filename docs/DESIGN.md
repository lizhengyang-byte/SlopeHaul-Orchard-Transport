# 设计说明 · SlopeHaul

本文按“命题 → 指标 → 方法 → 参数 → 验证”的顺序写，方便评委或工程师逐段核对；所有数值都能在 `slopehaul/config.py` 里找到出处。

## 1. 命题拆成四个可验证问题

命题要求“用人工智能地形感知与自适应控制支撑坡地重载运输”。把它压成四个能被仿真验证的问题：

1. **能不能判断这块坡走不走得了？** → 地形几何（坡度/横坡/粗糙度/台阶）+ 土壤类型 + 在线附着系数 → 可通行性代价与限速。
2. **负重在坡上会不会打滑？** → 牵引力需求与静摩擦能力的比值决定滑移；需要滑移闭环把轮子拉回线性区。
3. **停在坡上会不会溜？** → 驻车能力（制动 + 静摩擦）与坡道下滑分力的比较，不足则不释放制动。
4. **走向下坡会不会冲过头、侧翻？** → 制动距离反推允许初速 + 侧倾/俯仰几何包络。

## 2. 感知层

### 2.1 高程特征（`perception/elevation.py`）

对 0.15 m 栅格的深度高程图，在每个栅格上取 `5×5` 窗口做最小二乘平面拟合 `z = c0 + c1·s + c2·y`：

- 纵坡 `grade = atan(c1)`，横坡 `cross = atan(c2)`，合成坡度 `slope = atan(√(c1²+c2²))`；
- 粗糙度 = 去趋势残差的 RMS；
- 台阶 = 相邻栅格沿行进方向的**最大高差**（对长波起伏不敏感，专门抓真实落差）；
- 车辆足迹膨胀（默认 0.35 m）：把“车能过去”而不是“点能过去”作为判据。

初版曾用“窗口内最高减最低”当台阶，结果被 0.4 m 波长的起伏混叠成 0.21 m 假台阶，把整条下坡判成不可通行。改成相邻高差 + 把地形起伏波长限制在 ≥1.1 m（分辨率的 7 倍以上）后，台阶读数落到 0.05 m 量级。

### 2.2 土壤分类（`perception/soil_classifier.py`）

32×32 地表纹理提 8 维特征（亮度均值、标准差、梯度、拉普拉斯、熵、暗区占比、坡度、粗糙度），送入 8-16-4 的 numpy MLP（手写 Adam 训练，无 PyTorch 依赖），输出四类土壤及其 μ / 滚阻 / 坡度上限先验：

| 类别 | μ 先验 | crr | 坡度上限 |
|---|---|---|---|
| 压实土 | 0.80 | 0.030 | 28° |
| 草地 | 0.66 | 0.055 | 25° |
| 松软土 | 0.62 | 0.095 | 22° |
| 湿滑黏土 | 0.45 | 0.080 | 15° |

权重缺失时自动退化为规则分类器，保证无模型文件也能跑。

**这里必须说清楚**：纹理是合成代理数据，四类亮度/纹理差异被刻意放大。验证集 100% 只证明“当前合成分布可分”，不能当真实田间精度用。训练时特意加入曝光漂移（±10%）与传感器噪声（σ=0.015），避免模型只记住噪声统计——第一版加了 σ=0.045 的强噪声后，模型学到的是噪声而不是纹理，干净图像反而被误判成压实土，这也是一次真实的教训。

### 2.3 可通行性（`perception/traversability.py`）

- 坡度上限 = `min(土壤上限, 27°, atan(0.85·μ))`，把“摩擦允许”与“几何允许”取交集；
- 视觉先验为主，在线 μ 只做 ±0.05 / ±0.08 的小幅修正，防止单帧估计噪声把判定带偏；
- 由 `a_dec = μgcosθ − gsinθ − crrg` 反推制动初速 `v_brake = √(2·a_dec·d)`，再叠加曲率侧向约束与载重惩罚，输出 `v_limit / risk / cost / stopping_dist`；
- 判定不可通行时做 **3 帧连续确认**，避免坡度噪声导致反复启停。

## 3. 估计层

| 估计量 | 方法 | 关键约束 |
|---|---|---|
| 车速 | EKF，状态 `[v, b]`，IMU 加速度预测 + 轮速/视觉里程计自适应门限更新 | 打滑时轮速权重自动下降 |
| 附着系数 μ | 标量 RLS（遗忘 0.97），`μ_util = 牵引力 / ΣN` | 只在滑移 0.08–0.45 且 \|a\|<2 时更新；单步 ±0.08，限幅 0.25–0.88 |
| 滑移率 | 四轮独立 `(ωr − v)/max(ωr, v)` + 置信度 | 低速时置信度下降 |
| 载荷/质心 | 称重 + 坡度/加速度补偿 + 0.6 s 低通 | 输出 payload / 总质量 / 质心高 / 横向偏移 |

`μ_util` 的公式改过一次：早期写成 `(牵引力 + mg sinθ)/ΣN`，把重力重复计了一次，导致 μ 估计长期偏高 0.1 以上。

## 4. 车辆模型（`sim/vehicle.py`）

参数：整备 320 kg + 载重 200 kg，轴距 1.25 m，轮距 1.10 m，轮径 0.24 m，质心高 0.52→0.60 m（随载重），单轮峰值扭矩 190 N·m，制动 120 N·m。

### 4.1 附着曲线：静摩擦 → 峰值 → 滑移衰减

```
μ(s) = 1.12·μ_max           s = 0        （静摩擦，起步不空转）
μ(s) = μ_max                s = 0.18     （峰值，对应 slip_opt）
μ(s) = 0.55·μ_max           s = 1.0      （深度滑移，μ 崩溃）
```

三段线性插值，保证 s→0 有牵引力、s→1 有崩溃，中间没有跳变。

### 4.2 滑移用“平衡模型”而不是轮惯量积分

轮子转动惯量在 dt=0.02 s 下积分会数值发散（初版轮速一步冲到 slip=1、μ→0、车体倒溜 59 m）。改为按需求/能力比直接求滑移：

```
ratio = |F_demand| / F_static_cap
ratio > 1 → slip 以 (ratio−1)·2.5 的速率增长
ratio ≤ 1 → slip 以 0.25 s 时间常数衰减
traction = sign(F_demand)·min(|F_demand|, μ(slip)·N)
```

这等价于“轮子很快到达准静态滑移平衡”，牺牲了瞬态细节，换来了数值稳定与可控的物理含义。

### 4.3 其它必须处理对的细节

- **制动方向**：必须始终反运动方向，`|v|<0.03` 时收敛到 0。早期固定方向施加，在 v≈0 时把车“推着倒走”，S4 因此倒溜 43 m。
- **轴荷转移**：纵坡、横坡、侧向加速度共同决定四轮法向力；松软地面再按承载能力折减（这是“松软坡比硬坡更容易打滑”的物理来源）。
- **姿态滞后**：侧倾/俯仰用 τ=0.22 s 一阶滞后，避免瞬时限速抖动；超过 `atan(track/2h)` 判倾翻。

## 5. 控制层

### 5.1 速度规划（`control/adaptive.py: SpeedPlanner`）

`目标速度 = min(平路 1.35 m/s, 坡上 0.85 m/s) × 可通行限速 × 稳定性缩放 × 风险降速`，再过 0.45 s 低通。

### 5.2 纵向控制

```
扭矩 = 坡度前馈(1.15×mg sinθ) + 滚阻补偿 + 速度PI(抗饱和, 积分限±260)
      + 超速回馈制动(−0.35mg) + 后溜保护(+0.18mg)
再按四轮法向载荷分配，叠加滑移PI修正（只削减不加码，clip [−1,0]）
```

15% 的坡度补偿系数不是拍脑袋：S1 主坡提到 20° 后，纯前馈在 μ 波动时会反复“爬-滑振荡”，补 15% 才把需求压在静摩擦能力以内。

### 5.3 滑移闭环

轮级 PI：误差 = 实测滑移 − 目标滑移（0.18），输出只允许**削减**扭矩。这条“只减不加”的约束很关键——加了就会在附着恢复瞬间过驱，重新进入滑移。

### 5.4 稳定性包络（`control/stability.py`）

```
roll_cap  = atan(track/2h) × 0.75
pitch_cap = min(34°, atan(wheelbase/2h)) × 0.75
```

早期 pitch_cap 写死 34°×0.75=25.5°，20° 坡就误报 `STABILITY_WARNING`；改成几何推导后，俯仰上限随载重升高质心自动收紧，才不会误报也不会漏报。

### 5.5 驻车状态机（`control/hillhold.py`）

`DRIVE → BRAKING → HOLD → RELEASE`。HOLD 阶段比较 `min(制动能力, 静摩擦能力)` 与坡道下滑分力：

- 足够 → 保持，零溜坡；
- 不足 → `slipping=True`，累计 `slip_distance`，并在报告中暴露“这个坡本车停不住”的事实，而不是假装停住了。

### 5.6 安全监督（`control/safety.py`）

姿态 >45° 急停、稳定包络 critical 急停、不可通行拒绝、卡滞 3 s 触发 0.5 m 回退、电机 >85 ℃ 降载。

`safety_interventions` 早期按行计数，S1 出现 120 次“虚假介入”；改为**状态码变化次数**后，读数才有意义（S1 本方案 8 次，都是真实的限速/降载切换）。

## 6. 基线怎么设才公平

基线（`policy="baseline"`）不是“随便一个坏控制器”，而是**当前果园运输车常见的开环做法**：

- 定速 0.9 m/s；
- 四轮均分扭矩，无滑移闭环；
- 固定制动系数 0.45；
- 速度环增益 `0.6·m·err`（比本方案低，但仍是合理工程取值）。

于是差异只来自“有没有地形感知与自适应”，而不是“谁调参更狠”。

## 7. 评测口径

`eval/metrics.py` 固定 6 个关键指标：到达率、平均/P95 滑移率、最大侧倾、后溜距离、单位里程能耗。另外单列 `mu_est_mae`（估计可信度）与 `safety_interventions`（介入次数），避免“安全性靠多刹车刷出来”。

任务结论按场景期望判定：`reached`（应到达）、`safe_stop`（应拦停）、`failed`、`tipover`。S5 是“物理不可通行”场景，期望值就是 `safe_stop`——硬闯成功反而说明系统没有边界意识。
